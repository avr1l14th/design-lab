# Документация прототипа в Figma

Эталон: дока «Теги» — файл `Ma7dtZb6eSHJ5YoaiVEUn2`, страница «WIP Теги», секция `47347:189`, фрейм дока `47347:190`. Так должна выглядеть каждая следующая дока. Дизайнер и разрабы ее приняли, не изобретать другой формат.

## Что получается на выходе

Фрейм дока 2080 шириной с тремя блоками, сверху вниз:

1. **Описание** — нумерованный список, 6–8 пунктов, только общее про фичу.
2. **Таблица терминов** — колонки «Терм | RUS | ENG»: каждый видимый текст интерфейса (пункты меню, плейсхолдеры, тултипы, ошибки, тексты модалок и тостов, названия цветов).
3. **Таблица состояний** — колонки «Состояние | Дизайн»: строка на состояние, слева 1–4 предложения о поведении, справа макет.

## Порядок работы

### 1. Собрать факты, не сочинять

- Прочитать код прототипа в `app/<feature>/` целиком: стор, UI, фильтры, страницы. Выписать каждое правило поведения: что по клику, ховеру, Enter, Esc, клику мимо; лимиты, нормализацию, порядок, права, пустые состояния, ошибки, тосты, подтверждения.
- Прочитать память проекта (`project_<feature>.md`): решения дизайнера, отвергнутые варианты, уточнения.
- Проверить спорное в браузере (preview_start → javascript_tool), а не по памяти.
- Составить список состояний для таблицы: по одному на каждый экран/поповер/ошибку/пустое состояние. Обычно 10–14.

### 2. Написать тексты по правилам

Правила от дизайнера, нарушение = переделка:

- **Только поведение, сценарии, состояния.** Никаких размеров, цветов, радиусов, отступов, шрифтов — они есть в макетах.
- **Описание = только общее**: что это и кому принадлежит; где видно; права; правила имени/данных; порядок; общие правила поповеров и клавиатуры; поиск/фильтр; ссылки на прототип и код. 6–8 пунктов по 1–3 строки.
- **Все, что относится к конкретному элементу** (что делает клик, ховер, ошибка, что остается открытым) — в строке таблицы состояний рядом с макетом, не в описании.
- **Каждый факт один раз.** Если правило общее — в описании, из строк убрать. Если про элемент — в его строке, из описания убрать. Строки могут ссылаться: «то же меню, что по клику на чип».
- **Без вопросов в личку**: у каждого состояния должно быть понятно, что открывает, что происходит при действии, остается ли поповер открытым, есть ли подтверждение/тост, что с Enter/Esc.
- Русский, без буквы «ё», без сленга («сейм», «пох»), без вводных «как видно», «стоит отметить». Тексты интерфейса в «кавычках-елочках».
- Терминов не пропускать: пройтись по всем строковым литералам в коде (`grep -o '"[А-Яа-я][^"]*"'`) и по макетам.

### 3. Собрать фрейм в Figma

Через `use_figma` (перед вызовом загрузить `skill://figma/figma-use/SKILL.md`). Снипеты — в [references/figma-recipes.md](references/figma-recipes.md).

- Клонировать эталонный фрейм `47347:190` в новую секцию на странице фичи (страницы вида «WIP <Фича>» или «Q3'26 …»), переименовать заголовок и `Origin`.
- Описание: один текстовый узел, `characters` = пункты через `\n`, `setRangeListOptions` ORDERED на весь текст, ссылки через `setRangeHyperlink` + `setRangeTextDecoration` UNDERLINE.
- Таблицы: строки клонировать из существующих (`row.clone()` + `insertChild`), лишние удалить, тексты через `characters` после `loadFontAsync` для каждого сегмента.
- После любых правок подогнать секцию: `section.resizeWithoutConstraints(section.width, frame.y + frame.height + 100)`.

### 4. Снять макеты состояний из прототипа

Захват через `generate_figma_design` (fileKey файла, `nodeId` = временный пустой фрейм-холдер на странице дока). Тул возвращает capture script и `captureId`; страницу открывают по URL вида

```
http://localhost:3000/<путь>#figmacapture=<script>&figmaendpoint=<endpoint из ответа>&figmadelay=8000
```

`figmadelay` в миллисекундах выставляем сами: 8000 хватает, чтобы поставить состояние и прогнать инлайнер. Без хэша захват не запустится.

Порядок для каждого состояния, в одной вкладке подряд:

1. `navigate` на URL из тула (тот же путь с другим хэшем перезагружает страницу).
2. **Сразу же** (`javascript_tool`, без ожидания) поставить нужное состояние и запустить [scripts/inline-icons.js](scripts/inline-icons.js). Задержка захвата идет от загрузки страницы, укладываться за 1–1.5 с.
   - Состояние ставить кликами через DOM (`el.click()`), стор — через `localStorage` + reload до захвата.
   - Ховеры React не срабатывают от синтетических `mouseenter` — форсировать стили: `opacity`, `max-width`, `background-color`, показать тултип руками.
   - Инлайнер обязателен: иконки через CSS-маску и `<img *.svg>` иначе приезжают серыми квадратами.
3. Поллить `captureId` каждые 5 с. Захват может висеть pending 20–30 с — не перенавигировать раньше.
4. Проверить `parent` результата: захват с `nodeId` иногда ложится на страницу, а не в холдер — перенести `appendChild`. Удалить слои `LabFAB` и `PageFeedbackToolbarCSS`, если приехали.
5. Снимать на **своей** встрече/объекте пользователя, не на пошеренных (там ридонли).

Вьюпорт для захвата 1512×982 (`resize_window`), после работы вернуть `preset: "desktop"`, стор прототипа сбросить.

### 5. Фрагменты вместо полных экранов

Разрабам трудно искать глазами на полном экране, что изменилось.

- **Полный экран** оставлять для первого состояния каждого контекста (первый экран списка, фильтр целиком, первый экран страницы объекта) и для модалки поверх затемненного экрана.
- **Фрагмент** для остальных: область вокруг изменившегося элемента плюс якорь (строка списка целиком; поповер с колонкой-якорем от начала соседней колонки; шапка страницы с рядом чипов и поповером).
- Резать по границам блоков: не по середине заголовка даты, не обрывая email на «t.ai». Полная строка списка — 1232×80 от верха строки минус 6.
- Рецепт: фрейм `clipsContent` с белой заливкой и рамкой `#EFEFEF` 1px inside, внутрь клон экрана со сдвигом `x=-x0, y=-y0`, фрейм в ячейку `insertChild(0)`, старый экран удалить. Ячейка auto-layout ужмет строку сама. Клон внутри фрагмента полноценный — из него всегда можно вернуть полный экран.
- Модалка: экран + прямоугольник-затемнение `#212833` 30% поверх всего экрана (`layoutPositioning ABSOLUTE`, последний ребенок) + модалка `ABSOLUTE` по центру ячейки.

### 6. Проверить и сдать

- `get_screenshot` секции целиком и 2–3 строк крупно: тексты влезли, нумерация и ссылки на месте, фрагменты не режут текст.
- Перечитать все тексты как разраб: на каждый «а что если…» должен быть ответ в доке.
- В отчете дизайнеру: ссылка на секцию, сколько пунктов/терминов/состояний, что снято на каком экране, что не согласовано (макет расходится с прототипом).
- Записать в память проекта id секции/фрейма/таблиц и новые решения дизайнера.

## Что дизайнер отвергал

- Длинное описание с деталями состояний («месси структура, нейрослоп неструктурированный»).
- Размеры/цвета в тексте («оч много воды»).
- Полные экраны на каждое состояние («трудно смотреть на полный экран и искать глазами»).
- Фрагменты везде без исключений («ну не, ты прям везде обрезал, кое-где можно и оставить»).
